### Разбор отчёта по версиям — честная оговорка

Upstream разбирает отчёт не сам, а библиотекой `v8storage` (`packagedef` →
`.ЗависитОт("v8storage", "0.9.4")`) и берёт из неё поля `Номер`, `Автор`, `Дата`, `Комментарий`
(`МенеджерСинхронизации.ПрочитатьТаблицуИсторииХранилища`), причём теги в отчёте
не предоставляются — в upstream это прямо помечено комментарием `// теги в отчете не предоставляются`.

Исходники `v8storage` в этой итерации **недоступны** (библиотека не установлена локально,
сеть не использовалась). Поэтому `storage_report.parse_storage_report` написан по структуре
русскоязычного отчёта конфигуратора и **не сверялся с живым отчётом**. Парсер намеренно
устойчив: ключ берётся до первого двоеточия, поддержаны RU/EN подписи, многострочные
комментарии, разделители тысяч в номере версии. Фикстуры в `tests/` и
`examples/fixture-storage/` — **синтетические**, а не снятые с реального хранилища.
Это первое, что нужно проверить на стенде при приёмке.

## 5. Плагины

Upstream: `МенеджерПлагинов` + `МенеджерПодписок` (856 строк) — более 30 событий, часть с
изменяемым флагом `СтандартнаяОбработка`, установка пакетов через `opm`, встроенные
запакованные плагины (`bindata`), включение/отключение из CLI.

gitsync-py: `plugins.PluginHost` — Python-модули с `register(host)` и тремя событиями
(`after_history`, `before_commit`, `after_commit`) **без** подмены стандартной обработки.

**Ограничения заявлены явно**: плагины OneScript (`.os`) не загружаются и не будут загружаться;
подмена стандартной обработки (очистки каталога, выгрузки, чтения таблиц) не поддерживается;
установка плагинов через `opm` не поддерживается. Паритет по плагинам не заявляется.

## 6. Чего нет в итерации 1

* Docker-сценарии (по договорённости — вторая итерация).
* Работа с `ConfigDumpInfo.xml` и инкрементальной выгрузкой (`-update`).
* Метки/теги хранилища (`/ConfigurationRepositorySetLabel`).
* Команды блокировки/фиксации объектов хранилища (`Lock`/`Unlock`/`Commit`).
* Чтение конфигураций upstream в YAML/XML (`tests/fixtures/config.yaml`, `config.xml`).
* Push/merge/tag/release — сознательно: сетевые операции git не выполняются вообще.

## 7. Безопасность, восстановление, открытые швы

Поведение, добавленное по итогам независимого review (`review-01.md`, находки F01–F14):

| Свойство | Реализация | Примечание |
|---|---|---|
| Временные каталоги | `SyncManager._temp_root` создаёт `run-<uuid>` внутри переданного родителя и удаляет **только его** | родитель может быть общим для нескольких репозиториев и параллельных запусков; каталог внутри рабочей копии отвергается |
| Подтверждение выгрузки | `SyncManager._verify_export` | нет каталога — авария; пустой каталог допускается только при `backend.allows_empty_export` |
| Служебные пути из выгрузки | `sync.RESERVED_INPUT_NAMES`, `check_reserved_paths` | `.git`, `.GIT`, `.git.`, `git~1`, поток NTFS `имя:поток` — на любом уровне вложенности |
| Транзакция версии | журнал `.git/gitsync-py-journal.json` | подтверждением считается коммит в Git, а не маркер `VERSION`; незавершённая транзакция откатывается при следующем запуске (`SyncResult.rolled_back`) |
| Откат своих записей | `SyncManager._rollback_to_confirmed` | удаляются только пути из журнала, которых нет в индексе; чужие файлы не трогаются, `--allow-dirty` для восстановления не нужен |
| Ошибка после коммита | `SyncResult.post_commit`, `errors.PostCommitError` | коммит и маркер сохраняются, команда возвращает ненулевой код |
| Подкаталог `src` | авто-определение + `--disable-auto-src` | корень Git ищется через `git rev-parse --show-toplevel`; вложенный `.git` не создаётся, файлы вне подкаталога не трогаются |
| Блокировка | `locks.exclusive_lock` — блокировка ОС на дескрипторе | ядро освобождает её при аварии владельца (штатное восстановление), живой владелец не вытесняется; `sync` и `set-version` берут один и тот же файл `<git-dir>/gitsync-py.lock` |
| Маскировка секретов | `designer.redact_text`, `DesignerRunner.secrets` | вымарывается и argv, и stdout/stderr конфигуратора; цепочка исключений таймаута обрывается |

**Открытые швы (не закрыты в этой итерации, приёмкой не считаются):**

* `clone` не принимает Git URL (upstream `КомандаClone` клонирует репозиторий). Сетевые операции git не выполняются вообще — это остаётся сознательным ограничением, но паритет по команде не заявляется.
* Паритет плагинов не заявляется (§5): три события, без подмены стандартной обработки и приоритетов.
* Symlink-сценарии (`.gitignore` → внешний файл, файл блокировки → внешний файл) проверены только частично: на этом хосте нет прав на создание symlink (WinError 1314). Записи по ссылке предотвращены (`move_export_into_working_copy` снимает symlink перед записью, `exclusive_lock` отвергает symlink), но тест на стенде с правами не выполнен.
* Native E2E расширений и повторный прогон основной конфигурации после этих правок — отдельная задача (см. `native-product-e2e-02.md`, `native-extension-stand.md`).
