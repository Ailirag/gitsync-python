# Проверка серверного хранилища 1С через TCP

Дата: 20.09.2026. **PASS в границах изолированного стенда**.

## Среда и методика

Linux-контейнеры Docker на Ubuntu 24.04 / WSL2. Настоящий сервер хранилищ
`crserver` 8.3.27.2130 обслуживал копии трёх синтетических хранилищ:
конфигурации и двух именованных расширений. Клиент использовал `tcp://сервер:1542/имя`.
Каталоги хранилищ в клиентский контейнер **не монтировались**.

Проверялся установленный пакет неизменяемого native-образа stage19r1, без
подмены исходников томами. Идентификатор клиентского образа:
`sha256:4af770b9732e3f85cdcb1b91bcde7c0aab50098b2ac815e64f535e8b433a072d`.
Образы с проприетарной платформой не публикуются.

## Ограничения и первоначальный отказ

Первый прогон остановился до выгрузки из-за недоступности лицензии. После
переноса тестового crserver в отдельную внутреннюю сеть и подключения клиента
к ней и прежней лицензионной сети проверки прошли. Настройки раздачи лицензий
и firewall не менялись. Точная первопричина отказа отдельным сетевым A/B-тестом
не установлена. Это не доказательство устранения всех лицензионных отказов.

При остановленном сервере платформа возвращает неклассифицированную ошибку:
безопасный отказ подтверждён, но сообщение не объясняет недоступность сервера явно.

Проверены небольшие синтетические хранилища на одной версии платформы,
а не конкретный production-сервер, большие истории, HTTPS, разные версии платформы
или обрыв соединения посреди экспорта. Проверка двух расширений **по имени**
не доказывает работу режима `-AllExtensions`.

Для одного хранилища используйте единый URI и общий каталог сессий для
сотрудничающих процессов. DNS/IP-алиасы не объединяются автоматически;
локальная файловая блокировка не координирует произвольные внешние клиенты.

Тестовый сервер остановлен. Продуктовый код не изменялся. Полные логи и результаты
сохранены приватно; SHA-256 архива свидетельств:
`b9bbc997cf0b059b92c432666078120954051b46b6eafa327ccf73782f0568ec`.
