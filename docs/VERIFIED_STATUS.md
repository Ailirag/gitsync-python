# Проверенный статус и границы приёмки

Этот документ описывает результаты конкретного тестового стенда, а не гарантирует доступность чужого сервера лицензирования. Команды эксплуатации: [OPERATIONS_RU.md](OPERATIONS_RU.md).

## Что проверено

- **20.09.2026: настоящий сервер хранилищ `crserver` 8.3.27.2130 по TCP из Linux-контейнера**: jobs=1 и jobs=2, по 17/17 версий конфигурации и двух именованных расширений; XML совпали с независимым эталоном. Повторные запуски не изменили HEAD. Отказы аутентификации, отсутствующего хранилища и остановленного сервера не изменили Git. [Отдельный отчёт и границы проверки](SERVER_STORAGE_CHECK_RU.md).

- При переносе 71 файл исходников, тестов и Docker-файлов совпал по SHA-256 с кандидатом stage19r1. Затем в публикационной копии изменены документация, защитные gitignore-правила, комментарии Compose, quoting примера окружения и убрана пустая строка в конце теста. Исполняемый код `src/` не менялся.
- Публикационная копия установлена в отдельный venv Python 3.12 на Windows: **356 passed, 82 skipped**, код **0**; Ruff и сборка wheel/sdist прошли. Первоначальный запуск только через PYTHONPATH без установки пакета дал четыре import-ошибки дочерних процессов; после корректной установки полный прогон зелёный.
- Установленные errors.py, designer.py и sync.py в core/test/native stage19r1 совпали с исходниками.
- Независимый повтор полного pytest в неизменяемом test-образе, без сети и подмонтирования исходников: **419 passed, 19 skipped**, код **0**. Пропуски не считаются успешными native-тестами.
- Десять полных native-выгрузок на предыдущем и новом кандидатах в режимах jobs=1 и jobs=2: **17/17 версий** из трёх тестовых хранилищ; содержимое и полнота XML сверены с отдельным эталоном.
- Реальная параллельность jobs=2 подтверждена наблюдением процессов. Это не два последовательно выполненных задания очереди.
- Восстановление при однократном **искусственно введённом** отказе лицензии проверено отдельно: прежний вариант остановился на 11/17, новый завершил 17/17 после повтора. Это проверка реакции GitSync, не доказательство исправления сервера лицензий.

## Что НЕ доказано

- Первопричина редкого естественного отказа получения лицензии. Проблема воспроизвелась в отдельной контрольной пробе после выгрузки, не в десяти новых полных прогонах.
- Количество свободных мест лицензии: число одновременно успешных запусков не является серверной статистикой занятости.
- Причинная связь отказов с overlayfs или общим HOME. Контрольные опыты её не подтвердили; это не доказательство отсутствия любого влияния среды.
- Что ответ UDP сам по себе является отказом сервера: без декодирования статуса или серверного журнала такое заключение недопустимо.
- Неограниченная стабильность jobs=2. Ограниченные повторы повышают устойчивость к кратким сбоям, но исчерпываются при длительной недоступности.
- Защита от враждебного кода с тем же UID внутри того же контейнера. Используются только доверенные плагины. Приватный временный каталог предотвращает совместное использование scratch между обычными заданиями, но не изолирует от администратора Docker/хоста.

## Повтор лицензирования

Настроенный `retries` применяется к распознанным сообщениям отказа лицензирования в файле `/Out`. Между попытками — пауза 20 секунд, прерываемая отменой. Это выбранная инженерная настройка, а не измеренный таймаут освобождения лицензии. Обычные ошибки аутентификации хранилища не должны повторяться как ошибки лицензии.

## Публикация

В репозитории находятся исходники, тесты, инструкции и шаблоны. Проприетарная платформа 1С, лицензии, секреты, рабочие хранилища, VM и частные Docker-образы не публикуются. Платформа устанавливается из собственного законно полученного дистрибутива, лицензирование обеспечивается владельцем среды.

Для эксплуатационной приёмки нужен успешный прогон на собственных хранилищах и сопоставление результата с эталоном. Зелёный unit-тест или код завершения 0 сами по себе полноту выгрузки не доказывают.
